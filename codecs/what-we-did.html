What we did

← back to the results

We encoded one video with 4 different codecs at 5 different bitrates, measured how good it looks, how long it takes and how much energy it uses, and plotted everything. We did it twice: once in 1080p and once in 720p. This page lists every step and every command.

1. DASH vs HLS

  • First exercise (15 Oct): DASH, published on chriz133.github.io.
  • This exercise (19 Oct): the same thing with the other format, HLS.
  • Same 5 bitrates both times: 200k, 500k, 1M, 3M, 5M (1080p).

2. Setup (done once)

brew install vvenc vvdec                       # VVC encoder + decoder (ffmpeg cannot encode VVC)
python3 -m venv ../.venv                       # a private Python folder for this project
../.venv/bin/pip install codecarbon pandas matplotlib
  • vvenc / vvdec: programs that encode and decode VVC (also called H.266).
  • codecarbon: measures energy use. pandas: reads the result table. matplotlib: draws the plots.

3. Make the test clips

We use only the first 5 seconds of input.mp4, because vvenc is slow.

ffmpeg -i ../input.mp4 -t 5 -an -pix_fmt yuv420p -r 30 ref.y4m                          # 1080p
ffmpeg -i ../input.mp4 -t 5 -an -vf scale=1280:720 -pix_fmt yuv420p -r 30 ref720.y4m    # 720p
PartMeaning
-i filethe input file
-t 5only take 5 seconds
-anno audio
-vf scale=1280:720make the picture 1280x720 (the 1080p clip is not resized)
-pix_fmt yuv420pa standard colour format every encoder understands
-r 3030 frames per second
ref.y4mraw, uncompressed video: the "perfect original" we compare against

4. Encode, decode and measure

One script does everything: measure.py.

../.venv/bin/python measure.py        # 1080p, writes results.csv
../.venv/bin/python measure.py 720    # 720p,  writes results_720p.csv

4 codecs × 5 bitrates = 20 encodes per resolution. These are the encode commands inside the script:

ffmpeg -i ref.y4m -c:v libx264   -b:v 1000k out.mp4            # x264  (H.264)
ffmpeg -i ref.y4m -c:v libx265   -b:v 1000k out.mp4            # x265  (H.265)
ffmpeg -i ref.y4m -c:v libsvtav1 -b:v 1000k out.mkv            # SVT-AV1
vvencapp -i ref.y4m -b 1000k --preset faster -o out.266        # vvenc (H.266 / VVC)
PartMeaning
-c:v libx264which video codec (encoder) to use
-b:v 1000k / -b 1000ktarget bitrate: 1000 kbit/s. The encoder aims for it but misses a bit.
--preset fastervvenc speed setting: faster = quicker, but slightly worse compression
-o out.266the output file

Decoding

Decoding means turning the compressed file back into video. We time this too.

ffmpeg -i out.mp4 -f null -                  # decode and throw the result away
vvdecapp -b out.266 -o /dev/null             # the same for VVC
  • -f null - = decode everything but write nothing. /dev/null = the same idea (a trash bin).
  • -b = the compressed file to read. -o = where to write the decoded video.

How we measure

  • Time: Python's time.perf_counter() before and after the command.
  • Energy: CodeCarbon (OfflineEmissionsTracker) around the command, in Wh. On a Mac this is only an estimate (there are no real power sensors), so it mostly follows the run time.
  • Quality: we decode the file again and compare it with ref.y4m using ffmpeg filters:
ffmpeg -i decoded.y4m -i ref.y4m -lavfi "[0:v][1:v]psnr;[0:v][1:v]ssim;[0:v][1:v]libvmaf" -f null -
PartMeaning
[0:v][1:v]first input (the encoded video) vs second input (the original)
psnrpixel error in dB. Higher = better. Simple, but not how people really see.
ssimsimilarity from 0 to 1. 1 = identical.
libvmafNetflix's VMAF score, 0 to 100. Closest to what people see.
-lavfi"filter graph": run these filters on the videos

Every run becomes one row in the result csv (codec, bitrate, quality scores, time, energy).

5. How we plotted

../.venv/bin/python plot.py            # 1080p plots
../.venv/bin/python plot.py 720        # 720p plots (file names start with 720p_)
../.venv/bin/python plot.py compare    # 1080p vs 720p

plot.py is short and does the same thing for every plot:

  1. Read the result csv with pandas (one row per run).
  2. Split the rows by codec. Each codec gets its own line and colour.
  3. X axis = the real bitrate of each file (not the target), on a log scale with ticks at 200, 500, 1000, 3000, 5000.
  4. Y axis = the thing we measure: quality, time or energy. For time and energy the y axis is also logarithmic, because vvenc is much higher than the others and they would otherwise be squashed at the bottom.
  5. Save the picture as a PNG with matplotlib.

Good to know

  • vvenc is the slowest encoder (about 30–55 s for the 5 s clip at 1080p; the others take 4–12 s), which is why the clip is only 5 seconds.
  • If measure.py is stopped, just start it again. It skips the runs that are already in the csv.
  • The encoders do not hit the target bitrate exactly (for example SVT-AV1 asked for 5000k and got 5546k). That is why the plots use the real bitrate.
  • Energy is a CodeCarbon estimate on a Mac, so treat it as a rough comparison, not exact numbers.
